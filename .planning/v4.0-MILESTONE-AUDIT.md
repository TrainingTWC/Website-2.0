## Tech Debt Summary

### OFF-05 — firstOrderOnly Enforcement Gap (Non-blocking)

**Impact:** Repeat customers can claim and redeem firstOrderOnly discount codes.

**Root cause:**
- `validateDiscount` is called at claim time (ClaimOfferButton) with empty `customerPhone` → firstOrderOnly check is guarded by `if (discount.firstOrderOnly && args.customerPhone)` → silently skipped
- `submitOrder` re-validation only checks `expiresAt` + `maxUses`, not `firstOrderOnly`

**Remediation path:**
1. Add `firstOrderOnly` + `customerPhone` check to `submitOrder` re-validation (same index already exists)
2. OR: pass phone/email from checkout form to a pre-submit validation step before placing order

**Priority:** Medium — only affects firstOrderOnly-flagged codes; all other discount logic is correct.

---

### `(api as any)` Cast Pattern (All Phases)

**Files:** `EditorialCMS.tsx`, `EditorialHub.tsx`, `OrderConfirmation.tsx`

**Impact:** Type safety bypassed; IDE won't catch Convex API changes.

**Remediation:** Run `npx convex dev` after any schema changes to regenerate `_generated/api.d.ts`, then remove casts.

**Priority:** Low — no runtime impact; CI type-check would catch regressions.
