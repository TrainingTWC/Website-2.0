**Create `app/page.tsx`** (Phase 1 bridge — renders entire App.tsx client-side):

```tsx
"use client";

import dynamic from "next/dynamic";

// Phase 1 bridge: render entire App.tsx client-side.
// This is replaced by proper route files in Phase 3.
// ssr: false prevents server-side rendering of window/document-dependent code.
const App = dynamic(() => import("../src/App"), { ssr: false });

export default function Home() {
  return <App />;
}
```

Why dynamic + ssr: false:
- App.tsx uses window, document, localStorage, and Three.js — all browser-only
- With output: 'export', Next.js statically renders pages at build time in Node.js
- ssr: false skips server rendering → page.tsx builds as an empty shell
- App.tsx fills in on the client (identical to Vite SPA behaviour)
- Phase 3 replaces this with real App Router routes

| Boundary | Description |
|----------|-------------|
| GitHub Secrets → NEXT_PUBLIC_ env | Convex URL is injected at build time and bundled into client JS |
| Browser → Convex cloud | All API calls go to different-bulldog-772.convex.cloud over HTTPS |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-04 | Information Disclosure | NEXT_PUBLIC_CONVEX_URL in client bundle | accept | Convex deployment URLs are designed to be public; all auth is handled by Convex Auth server-side |
| T-01-05 | Spoofing | ConvexReactClient with hardcoded URL fallback | mitigate | `process.env.NEXT_PUBLIC_CONVEX_URL as string` — if undefined at build time, Next.js will warn; no fallback to attacker-controlled URL |
| T-01-06 | Tampering | deploy.yml modified to point to wrong artifact | accept | deploy.yml is version-controlled; changes are visible in git history; GitHub Actions requires repo write access to modify |
</threat_model>
