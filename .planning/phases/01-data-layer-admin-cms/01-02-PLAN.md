**Structure overview:**

**PostsManager (internal):**

State:
- `posts` = `useQuery(api.posts.listAll) ?? []`
- `discounts` = `useQuery(api.discounts.listDiscounts) ?? []`  (needed for flash-sale discount selector in form)
- `products` = `useQuery(api.products.list) ?? []`  (needed for linkedProduct selector)
- `showForm: boolean` — controls the creation/edit form slide-in panel
- `editingPost: Post | null` — null = creating, non-null = editing
- `uploading: boolean` — cover image upload in progress

Post list table columns: Headline (truncate to 40 chars), Type (colored badge), Status (colored badge), PublishAt (formatted date or "—"), Actions.

Type badge colors:
- `flash-sale` → amber background
- `product-launch` → violet background
- `cafe-news` → sky background
- `brand-story` → emerald background
- `champion` → rose background

Status badge colors: `draft` → stone, `published` → green, `scheduled` → blue

Row actions: "Edit" button (calls setEditingPost + setShowForm), "Publish/Unpublish" toggle button (calls `togglePublish` mutation), "Delete" button (confirm dialog, calls `deletePost` mutation).

"New Post" button top-right opens the form with editingPost = null.

**Post creation/edit form (slide-in panel or modal — use a fixed right-side panel):**

Fields and conditional display:
- `type` (select): all 5 options — changing type shows/hides conditional fields
- `headline` (text input, required)
- `subhead` (text input, optional)
- `body` (textarea, 6 rows, required)
- `status` (select): draft | published | scheduled
- `publishAt` (datetime-local input, optional)
- `expiresAt` (datetime-local input, optional — shown for flash-sale type)
- `linkedProductId` (select from products list, shown for product-launch and champion types)
- `discountId` (select from discounts list, shown ONLY when type = "flash-sale")
- Champion-only fields (shown ONLY when type = "champion"):
  - `personName` (text)
  - `personRole` (text)
  - `personStory` (textarea, 4 rows)
- Cover image upload:
  - File input (`accept="image/*"`)
  - On file select: call `generateUploadUrl` mutation → get URL → `fetch(url, { method: "PUT", body: file, headers: { "Content-Type": file.type } })` → on response, extract `storageId` from response JSON → set `coverImageStorageId` in form state
  - Show thumbnail preview if `coverImageUrl` exists on the post being edited
  - Show spinner when `uploading === true`

Submit handler:
- If `editingPost` is null: call `createPost` mutation with all form fields
- If `editingPost` is non-null: call `updatePost` mutation with `id = editingPost._id` + changed fields
- On success: close form, reset form state

**DiscountsManager (internal):**

State:
- `discounts` = `useQuery(api.discounts.listDiscounts) ?? []`
- `showForm: boolean`
- Form fields: code, discountType (percent | flat), amount, firstOrderOnly, expiresAt, maxUses

Discount list table columns: Code (monospace, bold), Type badge, Amount (show "X%" or "₹X"), First Order Only (✓/—), Expires, Max Uses, Used (usageCount), Delete action.

"New Discount" button top-right opens inline form (not a separate panel — simpler, fewer fields).

Create form submit: calls `createDiscount` mutation. Shows error toast if code already exists (catch ConvexError).

Delete action: `confirm("Delete discount code [CODE]?")` → calls `deleteDiscount`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Admin form → Convex mutations | Form data flows to createPost/createDiscount; schema validators are the last defense |
| File upload → Convex Storage | Cover images are PUT to a short-lived signed URL from generateUploadUrl |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Injection | post.body rendered in admin and later in hub | mitigate | Render as React text node `{post.body}` — never dangerouslySetInnerHTML |
| T-02-02 | Spoofing | generateUploadUrl is public (no auth) | accept | Consistent with rest of codebase; URL is short-lived (60s expiry per Convex) |
| T-02-03 | DoS | Malicious admin uploads very large image file | accept | Convex Storage enforces 20MB max file size by default |
| T-02-04 | Info Disclosure | listDiscounts exposes all codes to admin | accept | Admin intent; codes are meant to be shared publicly via offer cards anyway |
</threat_model>
