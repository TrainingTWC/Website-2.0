<objective>
Create two Next.js API route handlers (`/api/orders` and `/api/recommendations`) that act as server-side proxies to Convex. Migrate the two client components that currently call Convex directly (`CheckoutPage` and `BrewingStudio`) to use `fetch()` against the new routes instead of `useMutation`/`useAction`.

Purpose: After this plan, no mutation or action call crosses the trust boundary from browser to Convex directly. Every write goes through the Next.js server, which validates inputs and enforces rate limits.

Output: Two API route files + two updated client component files.
</objective>

  <action>
    Create `app/api/orders/route.ts` as a Next.js App Router route handler.

    **Input validation** (manual, no Zod — keep deps minimal):
    - Parse `request.json()` in a try/catch; return `400 { error: "Invalid JSON" }` on parse failure.
    - Validate the shape manually:
      - `customer.name` must be a non-empty string (trimmed)
      - `customer.phone` must match `/^\d{10}$/`
      - `customer.email` must contain `@` and a `.` after the `@`
      - `customer.address.line1`, `.city`, `.state` must be non-empty strings
      - `customer.address.pincode` must match `/^\d{6}$/`
      - `items` must be a non-empty array; each item must have `productId` (string), `name` (string), `qty` (positive integer), `price` (positive number)
      - `subtotal` must be a positive number
    - On validation failure: return `Response.json({ error: "..." }, { status: 400 })`

    **Rate limiting** (per IP, using Plan-01 utilities):
    - Call `getRateLimitKey(request)` to get the client IP.
    - Call `checkRateLimit(ip, 20, 60_000)` — 20 orders per minute per IP (handles bursts for large families, blocks automated spam).
    - If `false`: return `Response.json({ error: "Too many requests. Please wait a moment." }, { status: 429 })`

    **Forward to Convex**:
    - Call `await convexServer.mutation(convexApi.orders.submitOrder, validatedArgs)`
    - Return `Response.json(result, { status: 200 })` where `result` = `{ orderId: string }`
    - Wrap in try/catch: on `ConvexError` or any error, return `Response.json({ error: err.message ?? "Order submission failed" }, { status: 500 })`

    **Route must be `export const POST`** (App Router named export, not default).
    **Add `export const dynamic = "force-dynamic"`** at the top to opt out of static generation.

    Order of operations: validate input → rate limit → forward to Convex.
    Do NOT add CORS headers — same-origin requests from the Next.js app don't need them.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → /api/orders | Untrusted order payload; customer PII crosses here |
| Browser → /api/recommendations | Untrusted AI prompt args; controls Mistral spend |
| Next.js server → Convex | Trusted, server-side; URL is not exposed to browsers |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-proxy-05 | Tampering | `/api/orders` — price override | mitigate | Server validates structure; Convex `submitOrder` re-fetches DB price and overrides client price (existing server-side protection preserved) |
| T-proxy-06 | Denial of Service | `/api/recommendations` — AI cost abuse | mitigate | Rate limit 10 req/min per IP before forwarding to Convex/Mistral |
| T-proxy-07 | Denial of Service | `/api/orders` — order spam | mitigate | Rate limit 20 req/min per IP |
| T-proxy-08 | Injection | `/api/orders` — malformed customer fields | mitigate | Manual field validation rejects non-string, out-of-pattern, and missing required fields |
| T-proxy-09 | Information Disclosure | Error messages in API responses | mitigate | Return `err.message` on 500 (Convex errors are safe to surface); no stack traces |
| T-proxy-10 | Elevation of Privilege | Direct browser WebSocket to Convex for mutations | accept | Reads (useQuery) still go direct — acceptable since Convex auth gates sensitive data. Proxy covers all write paths. To fully block direct mutation calls, Convex functions would need HMAC header verification (deferred). |
</threat_model>
