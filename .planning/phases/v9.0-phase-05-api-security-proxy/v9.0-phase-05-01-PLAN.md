      - Gets (or initialises) the timestamp array for `key`.
      - Filters out timestamps older than `windowMs` from now.

      - NOTE: add a JSDoc comment — "In production on Vercel, x-forwarded-for is set by the edge network. On a single-instance server it reflects the real client IP."

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet → Next.js API route | Untrusted HTTP requests from any client |
| Next.js server → Convex cloud | Trusted internal call using server-held URL |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-proxy-01 | Tampering | `next.config.ts` security headers | mitigate | Add X-Content-Type-Options, X-Frame-Options, Referrer-Policy via `headers()` |
| T-proxy-02 | Information Disclosure | `NEXT_PUBLIC_CONVEX_URL` in client bundle | accept | URL is needed for reactive `useQuery` reads; exposure risk is low since Convex auth gates sensitive data |
| T-proxy-03 | Denial of Service | ConvexHttpClient singleton under load | mitigate | Plan-02 rate limiter caps per-IP request rate before forwarding to Convex |
| T-proxy-04 | Spoofing | `x-forwarded-for` manipulation for rate limit bypass | accept | Low-risk for a small coffee shop; upgrade to Upstash Redis + Vercel middleware if traffic scales |
</threat_model>
