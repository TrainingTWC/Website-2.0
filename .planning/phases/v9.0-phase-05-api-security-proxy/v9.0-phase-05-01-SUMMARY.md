# Phase v9.0-phase-05 — Plan 01 Summary

## What Was Built

Enabled Next.js server runtime and added foundational security infrastructure.

### Changes

**`next.config.ts`**
- Removed `output: "export"` — enables Next.js API routes and server runtime
- Added `async headers()` returning 5 security response headers for all routes:
  - `X-Content-Type-Options: nosniff`
  - `X-Frame-Options: DENY`
  - `X-DNS-Prefetch-Control: on`
  - `Referrer-Policy: strict-origin-when-cross-origin`
  - `Permissions-Policy: camera=(), microphone=(), geolocation=()`
- CSP intentionally omitted (THEME_BOOT_SCRIPT inline in layout.tsx would break without nonce strategy)

**`app/api/_lib/convex-server.ts`** (new)
- Server-side `ConvexHttpClient` singleton (`convexServer`)
- Re-exports typed `convexApi` (from `convex/_generated/api`) for clean import paths in API routes
- Startup guard: throws `Error` if `NEXT_PUBLIC_CONVEX_URL` is falsy

**`app/api/_lib/rate-limit.ts`** (new)
- Sliding window rate limiter using module-level `Map<string, number[]>`
- `checkRateLimit(key, limit, windowMs): boolean` — filters expired timestamps, returns false if over limit
- `getRateLimitKey(request): string` — reads `x-forwarded-for`, takes first IP, falls back to `"unknown"`
- Works per-worker (warm Vercel instance); upgrade path: Upstash Redis + `@upstash/ratelimit`

## Decisions Made

- No CSP header (would break inline THEME_BOOT_SCRIPT); deferred to a future nonce-based CSP phase
- Module-level Map for rate limiting accepted for small-scale deployment; documented upgrade path
