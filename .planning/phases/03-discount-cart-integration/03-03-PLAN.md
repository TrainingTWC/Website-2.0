D-03 rejection pattern (from CONTEXT.md):
```
If submitOrder rejects due to discount:
  1. Show toast: "This offer is no longer available. Your order has been placed without the discount."
  2. Call clearDiscount()
  3. Re-call submitOrder without discountCode
```

Note: In Plan 01, submitOrder does NOT throw on invalid discount — it silently drops it.
So the D-03 toast+retry path covers the case where Plan 01's server-side stripping
happens — the client does NOT get a ConvexError. Instead:
- The client should detect that the returned order has no discountCode
  even though one was sent, OR
- Simply always pass discountCode and trust Plan 01's silent drop.
The D-03 UX (toast + clear + re-submit) is therefore triggered ONLY on ConvexError
from submitOrder (e.g., network, auth, other DB error NOT related to discount).

Revised D-03 implementation: Keep the toast+retry logic but targeted only at
ConvexError messages that match "discount" or "offer". For the silent drop case
(Plan 01 design), the order goes through and no toast is shown — consistent with
"order must go through" intent. Document this clearly in the implementation.

      const doSubmit = async (withDiscount: boolean) => {
        return submitOrder({
          customer: { name, phone, email, address: { line1, line2, city, state, pincode } },
          items: cartProducts.map((c) => ({
            productId: c.product._id,

          clearDiscount?.();
          result = await doSubmit(false);

          throw err;  // re-throw non-discount errors
        }
      }

      onOrderCreated(result.orderId);
    } catch (err) {
      console.error("submitOrder failed:", err);
      setErrors({ name: "Something went wrong. Please try again." });
