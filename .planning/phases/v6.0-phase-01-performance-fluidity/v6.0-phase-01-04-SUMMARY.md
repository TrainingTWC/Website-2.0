# Plan v6.0-phase-01-04 — Heavy Component Tier Branching

## What shipped

- **`ProductHero3D`** — now consumes `usePerfMode()`; on `tier === "low"` or `reducedMotion` returns `null` and fires `onReady` on the next tick (so `ProductPage`'s static `<SmartImage>` fallback stays visible permanently). New optional `dpr?: [number, number]` prop; default resolves to `[1, 2]` on `high` and `[1, 1]` on `mid`. Existing `R3F` consumers gain pixel-density scaling without API changes.
- **`MagneticCursorLazy`** — rewritten as a tier-aware client component. Returns `null` unless `tier === "high"`, `!reducedMotion`, **and** `matchMedia("(pointer: fine)").matches`. Listens for `change` events to react to docking/undocking external mice.
- **`BestsellerCarouselFlat`** (NEW) — flat horizontal scroll-snap strip with `SmartImage` thumbnails, keyboard ←/→ nav, no `motion`/`r3f`/`three`. Used as the low-tier fallback.
- **`BestsellerCarousel3DLazy`** — now branches: `low || reducedMotion` → dynamic-loaded `BestsellerCarouselFlat`; otherwise → dynamic-loaded `BestsellerCarousel3D`. Three.js bundle is never requested on weak devices.
- **`GalaxySweep`** — new `variant?: "full" | "lite"` prop. `"lite"` is a single CSS-keyframe radial pulse (~600 ms, no rAF, no `motion` runtime work) that fires `onComplete` via `setTimeout`. The previous implementation is renamed `GalaxySweepFull` internally.
- **`GalaxySweepLazy`** — tier router: `low || reducedMotion` → `null` + immediate `onComplete`; `mid` → `variant="lite"`; `high` → `variant="full"`.

## Verification

- `npm run build` exits 0. Bundle sizes unchanged within rounding (e.g. `/` still 105 kB First Load JS).
- TypeScript clean.
- No call-site changes required: `ProductPage` still renders `<ProductHero3D>` directly; the existing `model3DReady` crossfade now resolves to "ready" instantly on low-tier so the flat image stays visible.

## Notes / scope

- `ShopPage` imports `GalaxySweep` directly (not `GalaxySweepLazy`) and was intentionally left untouched — out of scope for this plan.
- `BestsellerCarousel3DLazy` and `MagneticCursorLazy` have no in-tree consumers today; the tier-routing infrastructure is forward-compatible for any future use without re-wiring.
- `ProductHero3DLazy.tsx` is now redundant (gating moved into the component itself) but retained as a thin re-export to avoid breaking any downstream imports.

## Requirements satisfied

- PERF-10 — Heavy 3D / `r3f` work disabled on low-tier; mid-tier uses `dpr=[1, 1]`.
- PERF-11 — `MagneticCursor` and full-fidelity `GalaxySweep` only mount on `high` + fine pointer.

## Threat mitigations applied

- T-v6.0-01-05: Low-tier devices never request the Three.js / drei / r3f bundles for the bestseller carousel (dynamic split point gated **before** import).
- T-v6.0-01-06: `GalaxySweep` lite variant has zero rAF callbacks and no JS animation timeline — eliminating the rAF-storm risk on transition-heavy nav.
