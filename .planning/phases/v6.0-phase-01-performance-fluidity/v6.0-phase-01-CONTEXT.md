# Phase Context

## User Intent (Verbatim)

> now we need to work on the overall scrolling smoothness, refresh rate of the website,
> overall fluid and smoothness of the website. it needs to work flawlessly on a 8gb ram pc as well.

## Interpretation

The site already has a strong cinematic identity (Cinematic.tsx scrollytelling, Lenis smooth scroll,
3D bestseller carousel, magnetic cursor, GalaxySweep particle effect). Visually it lands; the
problem is that this stack stutters on mid-range hardware — specifically an 8 GB RAM Windows
laptop with integrated graphics, which is a realistic baseline for the Indian D2C audience.

The goal is **adaptive performance**: keep the high-end experience for capable devices,
gracefully degrade for everything else, without removing the brand feel. No "blanket disable
animations" — instead, instrument the device, classify it into a tier, and let each effect
opt into the right behavior for that tier.

## Decisions

| ID | Decision | Rationale |
|----|----------|-----------|
| D-01 | Three performance tiers: `low` / `mid` / `high`. Default tier is `mid` on SSR/missing signals | Avoids hydration flicker; `mid` keeps the brand alive without 3D heavy lifting |
| D-02 | Tier inputs: `navigator.deviceMemory`, `navigator.hardwareConcurrency`, `prefers-reduced-motion`, plus a one-time 60-frame rAF refresh-rate sample | Cheap, well-supported, no fingerprinting concern |
| D-03 | `prefers-reduced-motion: reduce` always forces `low` tier regardless of hardware | Accessibility takes precedence over visual flourish |
| D-04 | Tier classification rules: `low` if reducedMotion OR `deviceMemory ≤ 4` OR `hardwareConcurrency ≤ 4`; `high` if `deviceMemory ≥ 8` AND `hardwareConcurrency ≥ 8` AND estimated refresh ≥ 90 Hz; else `mid` | Catches the 8 GB RAM baseline as `mid`, integrated-GPU/4 GB as `low`, gaming laptops as `high` |
| D-05 | Lenis stays for `mid` and `high`, disabled for `low`. The synthetic `window.dispatchEvent(new Event("scroll"))` per rAF in `SmoothScroll.tsx` MUST go — it's the biggest single perf bug in the codebase | One global rAF that fires every scroll listener every frame is the textbook cause of multi-listener thrash |
| D-06 | Cinematic's per-chapter `useScroll` calls collapse into one shared top-level `useScroll` whose `scrollYProgress` is passed into chapter children, which use `useTransform` with section-local ranges (computed via `IntersectionObserver` offsets) | Eliminates N scroll listeners + N getBoundingClientRect calls per frame |
| D-07 | BestsellerCarousel3D `low`-tier fallback is a horizontal CSS scroll-snap strip of product cards (no rotation, no spring, no perspective). Mid keeps the current visual but without the lazy 3D Hero. High is unchanged | Preserves shopping value on low-spec; no blank rectangles |
| D-08 | `MagneticCursor` mounts only on `high` AND non-touch (`matchMedia("(pointer: fine)")`). Always off on touch | Cursor effect is meaningless on touch and expensive on weak CPUs |
| D-09 | Adopt `LazyMotion` + `domAnimation` at the provider root so `motion/react` ships ~20 KB less initial JS | Standard Framer Motion optimization; well documented |
| D-10 | Web vitals (FCP/LCP/INP/CLS/TTFB) captured via `web-vitals` library, posted to Convex via a new `webVitals.record` mutation. Dev logs to console | Real-user telemetry beats synthetic Lighthouse; gives us a way to verify the 8 GB UAT generalizes |
| D-11 | All image work goes through `next/image` (already configured for static export). Convex storage host must be allowlisted in `next.config.ts.images.remotePatterns`. Raw `<img>` only remains for tiny decorative SVG | CLS + LCP wins, no extra dependency |
| D-12 | Verification gate at end is a **manual** UAT checkpoint by the user on their actual 8 GB laptop. No automated FPS assertion (browsers don't expose it reliably from JS in a way that survives static export) | The user's lived experience IS the spec |

## Deferred Ideas

- Service worker / offline caching — wait until v7.0 PWA milestone if pursued
- Server-rendered above-the-fold cinematic (currently `ssr:false`) — risk of hydration mismatch with Lenis and motion; revisit only if LCP fails the budget
- Replacing Lenis with native CSS `scroll-snap` — out of scope, brand feel depends on Lenis momentum
- Switching from motion/react to a smaller animation library — too disruptive for marginal gain
- 3D hero on product page — already lazy and tier-gated by this phase; full rewrite deferred

## The Agent's Discretion

- Exact tier thresholds (D-04) are the agent's call within the spirit above
- Choice of `web-vitals` v3 API specifics (D-10)
- Whether to introduce a new `webVitals` table or extend `pageViews` (D-10) — the agent decides based on schema simplicity
- Whether to gate `GalaxySweep` mount via the tier hook directly or via a thin wrapper component
- Where exactly to call `LazyMotion` (top-level provider vs. per-route)

## Constraints

- Static export (`output: "export"`) — no SSR runtime, no edge functions
- GitHub Pages hosting (no Next.js image optimization endpoint at runtime — `unoptimized: true` already set or required)
- Convex 1.38, React 19, Next.js 15.3.2, motion/react 12, Tailwind v4
- Cannot break existing flows: home cinematic, shop grid, product page (hero 3D), cart, checkout, journal, admin
- Convex schema changes require migration consideration (see `convex/_generated/ai/guidelines.md`)
