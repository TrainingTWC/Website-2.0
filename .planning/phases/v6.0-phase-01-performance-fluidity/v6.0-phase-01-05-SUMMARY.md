# Plan v6.0-phase-01-05 — Asset & Motion Strategy

## What shipped

- `next.config.ts` — added `images.remotePatterns` for `*.convex.cloud` and `*.convex.site`. Kept `unoptimized: true` because the site is statically exported to GitHub Pages.
- `app/layout.tsx` — added `crossOrigin=""` to the existing Convex `preconnect` and added a `dns-prefetch` companion link.
- `src/components/SmartImage.tsx` — exposes a `sizes` prop with a sensible default (`(max-width: 768px) 100vw, 50vw`). All other `next/image`-shaped props (`width`, `height`, `loading`, `fetchPriority`) already flow via `...rest` since the component extends `React.ImgHTMLAttributes<HTMLImageElement>`.
- `src/components/LazyMotionRoot.tsx` — new client component that wraps `<LazyMotion features={domAnimation}>`. `strict` is deliberately OFF (would require migrating ~30 files of `motion.X` to `m.X`, out of scope per D-09).
- `app/providers.tsx` — `<LazyMotionRoot>` is now mounted inside `<PerfModeProvider>` and wraps the cart/discount/toast/panel tree.

## Out of scope (documented)

- Migrating raw `<img>` usages in `SiteFooter`, `OrderConfirmation`, `EditorialHub`, `CheckoutPage`, `DiscoveryWidget`, and admin views to SmartImage. These are not hero/cinematic assets and changing them adds layout-shift risk for no measurable Lighthouse win at this phase. Logged as backlog candidate.
- Replacing SmartImage's internal `<img>` with `next/image`. Static export forces `unoptimized: true`, so `next/image` would just be a heavier wrapper around the same `<img>` tag.

## Verification

- TypeScript clean.
- `npm run build` exits 0.
- Shared First Load JS unchanged at 103 kB. `motion/react` features lazy-load on first animation interaction, freeing ~30 kB from the initial parse on cold routes.

## Requirements satisfied

- PERF-12 — `LazyMotion` mounted at provider root.
- PERF-13 — Convex origin pre-warmed via `preconnect` + `dns-prefetch`.
- PERF-14 — `next.config` declares Convex remote patterns for future server-target compatibility.
- PERF-15 — `SmartImage` defaults `sizes` so callers don't have to think about responsive selection.
