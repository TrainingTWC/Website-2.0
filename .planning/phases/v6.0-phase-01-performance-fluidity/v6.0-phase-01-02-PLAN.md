<objective>
Fix the highest-leverage perf bug in the codebase: `SmoothScroll.tsx` dispatches a fake `scroll` Event every animation frame to keep motion/react `useScroll` in sync with Lenis. Every motion `useScroll` listener (and there are many — Cinematic alone has eight per-chapter listeners) re-evaluates on every frame, even when the scroll position has not changed and even when the section is off-screen. This is the textbook cause of "fluid on M1 Mac, choppy on 8 GB laptop."

Replace the synthetic dispatch with Lenis's own `scroll` event callback (Lenis already emits a native-shaped `scroll` event on the window when its position changes, which motion/react reads natively). Also gate Lenis initialization on tier: `low` and reducedMotion users get native browser scroll.

Purpose: One change, measurable FPS win across the entire site. No API changes — `smoothScrollTo` and `window.__lenis` keep working.

Output: A trimmer `SmoothScroll.tsx` that is tier-aware.
</objective>

Lenis 1.3+ exposes:
- `lenis.on("scroll", (e) => { ... })` — fires only when scroll actually moves.
- `lenis.raf(time)` — manual rAF driver (still required).
- `lenis.scrollTo(target, opts)` — unchanged.
