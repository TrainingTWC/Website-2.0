<objective>
Cinematic's `ChapterReveal` currently calls `useScroll({ target: ref, offset: [...] })` once per chapter. With ~5 chapters that's 5 scroll listeners, each running `getBoundingClientRect` on every Lenis tick. Plan 02 already cut the dispatch frequency; this plan eliminates the listener count and adds IO-gated `will-change` plus a tier-aware parallax kill-switch.

Purpose: Cinematic is the visible centerpiece of the home page and the most likely place a 8 GB laptop stutters. Consolidating its scroll listeners and gating GPU promotion are the two biggest wins after the Lenis fix.

Output: A `ChapterDeck` that holds a single top-level `useScroll` (window-relative) and uses chapter-local ranges via `useTransform`. `ChapterReveal` receives the shared `scrollYProgress` plus its own viewport range (computed from layout) and derives all transforms locally. On `low` tier / reduced motion it bypasses transforms entirely.
</objective>

<interfaces>
Existing `ChapterDeck` renders a `<section>` per chapter and each chapter is a `<ChapterReveal>` with its own `useScroll`. Replace the pattern with:

```ts
// In ChapterDeck:
const deckRef = useRef<HTMLDivElement>(null);
const { scrollYProgress } = useScroll({
  target: deckRef,
  offset: ["start end", "end start"],
});

// For each chapter i out of N:
const localStart = i / N;
const localEnd = (i + 1) / N;
// pass scrollYProgress + [localStart, localEnd] into ChapterReveal
```

`ChapterReveal` then composes transforms with `useTransform(scrollYProgress, [localStart, localEnd], [...range...])`. Each chapter still has its own ref (for IntersectionObserver gating of `will-change`) but no longer creates a scroll listener.
</interfaces>
