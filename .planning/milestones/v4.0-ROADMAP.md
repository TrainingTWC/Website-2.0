## Overview

Built a fully dynamic, CMS-driven editorial system that feels like a premium coffee magazine. Admins can create flash sales, product launches, café news, brand stories, and champion spotlights entirely through the Admin Dashboard. Users see a magazine-style hub with live countdown timers, a glassmorphism "Claim Offer" mechanic, and a seamless discount flow from editorial card → cart drawer → checkout → order record.

## Milestone Summary

### Key Decisions

| Decision | Rationale |
|----------|-----------|
| "Claim Offer" glassmorphism button (not silent auto-apply) | User intent is clear; confirmation toast prevents accidental claims |
| One active discount per cart session | Simplest UX; prevents stacking abuse |
| Discount validation server-side in submitOrder (D-03) | Security — never trust client total; server ignores args.total |
| Discount state in App.tsx, no useCart.ts (D-01) | useCart.ts refactor deferred to Next.js migration |
| Modify CartPanel.tsx in place (D-02) | ROADMAP mistakenly named CartDrawer.tsx; file is CartPanel.tsx |
| Server-side silent drop on invalid discount (D-03) | "Order must go through" — ConvexError only triggers D-03 retry path |
| Cover images stored in Convex Storage | Consistent with existing product image pattern |
| Magazine grid CSS only (no new layout library) | Tailwind grid covers all needs; no extra bundle weight |

### Issues Encountered

- ROADMAP spec assumed `useCart.ts` and `CartDrawer.tsx` existed — neither was created in v2.0 (cart state was wired directly in App.tsx). Resolved via discuss-phase decisions (D-01, D-02).
- `(api as any)` cast pattern required in EditorialCMS.tsx, EditorialHub.tsx, and OrderConfirmation.tsx — Convex type generation not re-run after adding new tables.
