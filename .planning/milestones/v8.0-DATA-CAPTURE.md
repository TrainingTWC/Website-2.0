# Data Capture Spec: v8.0 — CRM & Order Fulfillment

**Companion to:** `v8.0-REQUIREMENTS.md` and `v8.0-FAILURE-MODES.md`
**Purpose:** Define every event that must be captured, the exact field schema, where it's stored, and what question it answers. If a metric isn't sourced from one of the events here, it isn't trustworthy.

**Storage targets:**
- `customerEvents` — high-fidelity per-customer timeline (Convex table, indexed by `customerId`)
- `orderEvents` — every state transition on an order (Convex table, indexed by `orderId`)
- `pageViews` — already exists; not duplicated here
- `webVitals` — already exists; out of scope
- `clientErrors` — NEW table for frontend exceptions
- `webhookFailures` — NEW table for inbound webhook failures
- `auditLog` — already exists for admin actions

---

## 1. Cart Lifecycle Events (write to `customerEvents`)

All cart events fire from the client. Anonymous events go to `customerEventsAnonymous` keyed by `sessionId` and are merged on identification (EVT-03).

| Event | Trigger | Required Properties | Optional Properties | Question it answers |
|-------|---------|---------------------|--------------------|--------------------|
| `product_viewed` | Product detail page mount | `productId`, `name`, `price`, `category`, `source` (`shop \| editorial \| widget`) | `referrerProductId`, `dwellMs` (on unmount) | Which products draw attention but don't convert? |
| `cart_item_added` | Add-to-cart click | `productId`, `qty`, `unitPrice`, `cartValueAfter`, `cartItemCountAfter` | `discountApplied` (if active code) | Conversion rate from view → cart |
| `cart_item_removed` | Remove-item click | `productId`, `qty`, `cartValueAfter` | `reason` (if a remove-reason modal is shown) | Why do customers de-stuff carts? |
| `cart_qty_changed` | Qty +/- | `productId`, `qtyBefore`, `qtyAfter`, `cartValueAfter` | — | Frequency of qty adjustments |
| `cart_opened` | Cart drawer opens | `cartItemCount`, `cartValue`, `source` (`header \| auto \| recovery_link`) | — | Drawer-open → checkout funnel |
| `cart_validated` | Result of `cartValidate` query | `priceChangedCount`, `outOfStockCount`, `removedCount` | — | Stale-cart rate (proxy for site freshness) |
| `cart_recovered` | Customer arrived via `?recover={token}` | `cartSnapshotId`, `ageMinutes` | `templateKey` (which abandoned-cart email triggered it) | Recovery campaign effectiveness |
| `checkout_started` | Checkout page mount | `cartValue`, `cartItemCount`, `discountCode?` | — | Cart → checkout step rate |
| `checkout_field_completed` | Blur on a required field | `field` (`name \| phone \| email \| line1 \| pincode`) | — | Where in the form do people drop off? |
| `checkout_abandoned` | Page unload before submit | `lastFieldCompleted`, `cartValue`, `timeOnPageMs` | — | Abandonment funnel by step |
| `checkout_submit_attempted` | "Place Order" click | `cartValue`, `paymentMethod`, `discountCode?` | — | Friction at the final click |
| `checkout_submit_failed` | `createDraftOrder` returned error | `errorCode`, `errorMessage` | — | What blocks orders right at the gate? |

**Required base properties on every event (auto-injected by client emitter):**
```ts
{
  ts: number,           // Date.now()
  sessionId: string,    // localStorage twc_session_id (uuid)
  customerId?: string,  // set after identification
  page: string,         // window.location.pathname
  referrer?: string,    // document.referrer
  deviceTier: "low" | "mid" | "high",  // from existing perf tier system
  userAgent: string,    // server-truncated to 200 chars
}
```

## 2. Order Lifecycle Events (write to `orderEvents`)

Every state transition is logged. Schema:

```ts
orderEvents: {
  orderId: string,                          // "TWC-XXXXXXXX"
  from: OrderStatus | null,                 // null on creation
  to: OrderStatus,
  actor: string,                            // "customer" | "admin:{userId}" | "system:{cronName}" | "webhook:{razorpayEventId}" | "courier:{partner}"
  reason: string,                           // free-text, indexed for search
  ts: number,
  metadata: string,                         // JSON-stringified blob, schema below per event
}
```

| Transition | `actor` source | Required `metadata` |
|------------|----------------|--------------------|
| `null → draft` | `customer` | `{ cartValue, paymentMethod, pincode, holdsCreated: [{productId, qty}] }` |
| `draft → pending` | `webhook:{razorpayEventId}` OR `customer` (COD) | `{ paymentId?, paymentMethod, totalCharged }` |
| `draft → payment-failed` | `webhook:{razorpayEventId}` | `{ failureCode, failureReason }` |
| `draft → expired` | `system:expireDrafts` | `{ ageMinutes, holdsReleased }` |
| `pending → cod-verification` | `system:codRiskCheck` | `{ riskReasons: string[], threshold: number }` |
| `pending → confirmed` | `admin:{userId}` OR `system:codAutoConfirm` | `{ otpVerified?: bool }` |
| `pending → cancelled-by-customer` | `customer` | `{ reason }` |
| `pending → cancelled-by-ops` | `admin:{userId}` | `{ reason, otpVerified: true }` |
| `confirmed → packed` | `admin:{userId}` | `{ packedBy, internalNotes? }` |
| `packed → shipped` | `admin:{userId}` | `{ trackingId, courier, shippedAt, expectedDeliveryDate }` |
| `shipped → delivered` | `courier:{partner}` OR `admin:{userId}` | `{ deliveredAt, signedBy?, podUrl? }` |
| `shipped → delivery-failed` | `courier:{partner}` | `{ ndrAttempts, ndrReason, willRetry: bool }` |
| `delivery-failed → shipped` | `admin:{userId}` | `{ rescheduledFor }` |
| `delivery-failed → returned` | `system:rtoAfterMaxAttempts` OR `admin:{userId}` | `{ rtoReason }` |
| `shipped → lost-in-transit` | `admin:{userId}` | `{ courierClaimId? }` |
| `delivered → return-requested` | `customer` | `{ reason, lineItems: [{itemId, qty, reason}] }` |
| `return-requested → returned` | `admin:{userId}` | `{ receivedAt, resellable: bool, photoUrl? }` |
| `returned → refunded` | `webhook:{razorpayRefundId}` OR `admin:{userId}` (manual) | `{ refundAmount, refundMethod, refundId }` |
| `* → * (force)` | `system:force` (superadmin only) | `{ overrideReason, otpVerified: true }` |

**Indexes:** `by_order_ts` (primary timeline view), `by_actor` (audit by actor), `by_to_ts` (queue: "all orders that entered state X in window").

## 4. Payment Events (`orderEvents` + `paymentLog`)

Razorpay webhooks already cover state transitions on `orderEvents`. ADDITIONALLY, write a raw `paymentLog` row for every payment-related interaction (queries AND webhooks) — this is the immutable ledger for finance reconciliation.

```ts
paymentLog: {
  ts: number,
  direction: "outbound" | "inbound",       // outbound = our API call to RZP; inbound = webhook
  endpoint: string,                        // "/orders" | "/payments/{id}/refund" | "webhook:payment.captured"
  razorpayOrderId?: string,
  razorpayPaymentId?: string,
  razorpayRefundId?: string,
  ourOrderId?: string,
  amount?: number,                         // paise
  status: "success" | "failure",
  httpStatus?: number,
  errorCode?: string,
  responseSnippet: string,                 // first 500 chars of body, PII-stripped
}
.index("by_ourOrderId", ["ourOrderId"])
.index("by_ts", ["ts"])
```

Question this answers: "What did Razorpay actually tell us about order X, in order?" Critical for chargeback disputes.

## 5. Inventory Events (write to `inventoryEvents`)

```ts
inventoryEvents: {
  productId: Id<"products">,
  delta: number,                            // negative = consumed, positive = restocked
  reason: "hold_created" | "hold_released" | "order_finalized" | "return_restocked" | "admin_adjust" | "write_off",
  refOrderId?: string,
  refHoldId?: string,
  byActor: string,
  ts: number,
  stockAfter: number,                       // snapshot post-mutation
}
.index("by_product_ts", ["productId", "ts"])
```

Question this answers: "Why is the stock count what it is right now? Show me every change."

## 7. Client Error Capture (`clientErrors`)

```ts
clientErrors: {
  ts: number,
  sessionId: string,
  customerId?: string,
  url: string,
  errorMessage: string,
  errorStack?: string,           // truncated to 2KB
  componentName?: string,        // from React error boundary
  userAgent: string,
  appVersion: string,            // from build-time env
  context: string,               // JSON: { route, cartValue?, orderId? }
}
.index("by_ts", ["ts"])
.index("by_session", ["sessionId"])
```

**Wired via:** `window.addEventListener("error" | "unhandledrejection")` + React `ErrorBoundary` + explicit `logClientError()` calls in critical paths (cart, checkout, payment).

**Sampling:** 100% on checkout/payment routes; 10% elsewhere to control volume.

## 8. Webhook Failures (`webhookFailures`)

```ts
webhookFailures: {
  ts: number,
  endpoint: string,                  // "/razorpay/webhook" | "/courier/webhook"
  reason: "signature_invalid" | "body_malformed" | "duplicate_event" | "handler_threw",
  signatureHeader?: string,          // first 20 chars only
  bodySnippet: string,               // first 1KB
  remoteIp?: string,
  errorMessage?: string,
}
.index("by_ts", ["ts"])
```

**Alert threshold:** >10 signature_invalid in 1 hour OR >5 handler_threw in 5 minutes → ops paged.

## 9. Derived Metrics (computed via Convex queries, not stored)

| Metric | Definition | Used by |
|--------|------------|--------|
| **GMV (Gross Merchandise Value)** | `sum(orders.total)` where `status in (confirmed, packed, shipped, delivered)` over a window | Finance dashboard |
| **Net Revenue** | GMV - `sum(refunds.amount where status=processed)` | Finance dashboard |
| **Cart-to-Checkout Rate** | `count(checkout_started) / count(cart_opened)` (distinct sessions) | Funnel report |
| **Checkout Completion Rate** | `count(orders where status != draft) / count(checkout_started)` | Funnel report |
| **COD Rejection Rate** | `count(orderEvents where to=cancelled-by-ops AND reason contains 'cod')` / `count(orders where paymentMethod=cod)` | Risk dashboard |
| **NDR Rate** | `count(orderEvents where to=delivery-failed) / count(orderEvents where to=shipped)` | Logistics dashboard |
| **Abandoned Cart Recovery Rate** | `count(cart_recovered → ... → order_placed in 7 days) / count(carts marked abandoned)` | Marketing |
| **Avg Time-to-Delivery** | `avg(delivered.ts - confirmed.ts)` per pincode/courier | Logistics |
| **Avg Time-in-State** | `avg(transition out.ts - transition in.ts)` per state | Ops bottleneck analysis |
| **Repeat Customer Rate** | `count(customers where orderCount > 1) / count(customers)` | CRM dashboard |
| **LTV (90-day)** | `sum(lifetimeRevenue where firstOrderAt < now - 90d)` / count | CRM dashboard |
| **Refund Rate** | `count(orders where status=refunded) / count(orders where status in (delivered, returned, refunded))` | Quality dashboard |
| **Notification Deliverability** | `count(notification_delivered) / count(notification_sent)` per channel | Comms dashboard |

## 10. Privacy & Retention

| Data | Retention | Why |
|------|-----------|-----|
| `customerEvents` (low-value) | 90 days | Funnel analysis is short-window |
| `customerEvents` (high-value: orders, refunds, consent) | 7 years | Tax/compliance + customer record |
| `orderEvents` | 7 years | Tax audit requirement |
| `paymentLog` | 7 years | Finance + chargebacks |
| `inventoryEvents` | 2 years | Inventory audit |
| `clientErrors` | 30 days | Debugging only |
| `webhookFailures` | 90 days | Long enough to debug provider issues |
| `pageViews` (raw) | 30 days | Aggregated to `pageViewDailySummary` (already shipped) |
| `auditLog` | Indefinite | Admin actions never deleted |

**PII handling:**
- `phone` stored E.164, displayed as `+91-XXXXX-1234` to non-superadmin
- `email` stored lowercased, displayed as `j****@gmail.com` to non-superadmin
- `address` shown in full to `orders:true` permission, abbreviated `City, State` to others
- DPDP deletion request: scrub `name`, `email`, `phone` to `null`; replace with hash; keep `customerId` and order linkage for tax purposes

## 11. Schema Migration Order

When implementing in Phase 1 (CRM data foundation), add tables in this order (each is independent and additive):

1. `customers` + `customerAddresses` + `pincodeServiceability`
2. `customerEvents` + `customerEventsAnonymous`
3. `inventoryHolds` + `inventoryEvents`
4. `orderEvents` (new — replaces ad-hoc audit; existing orders backfilled with synthetic `null → {currentStatus}` events)
5. `paymentLog` + `webhookFailures` + `processedWebhookEvents`
6. `refunds` + `writeOffs`
7. `notificationOutbox` + `cronLocks`
8. `customerSegments` (materialized view, populated by trigger)
9. `cartSnapshots` + `productWaitlist`
10. `clientErrors`

Each migration is a separate Convex deploy; the app must continue to function with old + new schema simultaneously (additive only, no breaking renames).
